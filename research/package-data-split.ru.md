# Общие карты, локализация и редакции данных Perfect World 1.7.6

Проверка 23 ноября 2026 года. Сравниваются выбранные в `gs.conf` данные из `Linear/PWServer176.7z` (RU Build 4311) и `RageZone/pw_server_1.7.6_2025.gz` (Sranus, активные CN-данные). Для карт сопоставлены пути относительно `pwserver/` и SHA-256. Для игровых таблиц сопоставлены записи и отдельные поля. [Архивы и выбранные файлы](server-distribution-comparison.ru.md) · [Сравнение вариантов ИИ и заданий](server-locales.ru.md)

## Что совпадает в обоих комплектах

- В 113 каталогах карт **3 909 файлов** совпали по пути и SHA-256. Их объём **4 785 427 853 байта** до сжатия, около 99,7% объёма файлов этих каталогов у Linear. У 13 экземпляров `world/мусор/` из Linear есть побайтовые копии под `world/` у Sranus.
- Среди путей карт, присутствующих в обеих поставках, различаются два `npcgen.data`. В `a108` у Linear 126 групп спавна, у Sranus 2. В `world` 21 520 и 21 516 групп соответственно, при одинаковых записях ресурсов и динамических объектов. Обе версии Sranus совпали по SHA-256 с соседними копиями `npcgen-orig.data` в Linear. Авторство и происхождение обеих редакций спавнов остаются открытыми.
- Совпали все четыре `gshop*.data`, `dyn_tasks.data`, `world_targets.sev` и `wmgj.nmd`. Обе поставки используют эти же байты при разных основных заданиях. [Каталоги карт](evidence/pwserver-files/map-directories.csv) · [Инвентарь серверных комплектов](server-distribution-comparison.ru.md)

Совпали все параметры соответствующих секций, включая `index`, `tag` и `base_path`. Алиасы используют 107 разных тегов и 101 каталог ресурсов. Все 101 каталог присутствуют в обоих архивах. `gs.conf` Talolan с RU-данными совпал с Linear по SHA-256. ## Совместимость при замене файлов

- **Монстр и ИИ.** `MONSTER_ESSENCE.common_strategy` в `elements.data` указывает на ID политики. Если `gs` не находит его в загруженном `aipolicy.data`, он пишет сообщение в журнал и обнуляет ссылку на политику этого шаблона. Уже в активной паре Linear у 397 шаблонов есть ссылки на 226 разных ID из 261, добавленного в `5385` относительно `5124`. Пример — монстр 70947 и политика 5125. Это проверка всех записей таблицы, включая шаблоны, которые могут не использоваться на карте. [Подключение политики к монстру](https://github.com/huzeming/176source/blob/c0992a29c0848de4de139a8958ceb11edcf2d38b/cgame/gs/npcgenerator.cpp#L218-L230)
- **Спавн и таблицы.** ID монстра или NPC из `npcgen.data` должен разрешаться в `elements.data`. При отсутствии шаблона `gs` пропускает запись спавна. ИИ и задания также активируют контроллеры спавна по ID. Для отсутствующего контроллера соответствующая активация ничего не создаёт. [Загрузка спавна](https://github.com/huzeming/176source/blob/c0992a29c0848de4de139a8958ceb11edcf2d38b/cgame/gs/npcgenerator.cpp#L4212-L4223) · [Поиск контроллера](https://github.com/huzeming/176source/blob/c0992a29c0848de4de139a8958ceb11edcf2d38b/cgame/gs/npcgenerator.cpp#L4087-L4107)
- **Задания.** Сервисы выдачи и сдачи у NPC ссылаются на ID заданий. Задания, в свою очередь, содержат ссылки на NPC, цели-монстров и предметы. В Linear NPC 43095 встречается в записях спавна `world/npcgen.data` и через `NPC_TASK_OUT_SERVICE` 43097 ссылается на задание 36625. Этот ID есть в RU `tasks.data` и отсутствует во всём CN `tasks.data` и в общем `dyn_tasks.data`. При подмене только `tasks.data` код сервера вернёт `ERR_TASK_NOT_AVAILABLE` на попытку взять этот квест. При загрузке сохранённых активных заданий он также ищет шаблон по ID. [Сервис NPC](https://github.com/huzeming/176source/blob/c0992a29c0848de4de139a8958ceb11edcf2d38b/cgame/gs/serviceprovider.cpp#L1233-L1241) · [Проверка выдачи](https://github.com/huzeming/176source/blob/c0992a29c0848de4de139a8958ceb11edcf2d38b/cgame/gs/task/TaskServer.cpp#L539-L598) · [Восстановление активных заданий](https://github.com/huzeming/176source/blob/c0992a29c0848de4de139a8958ceb11edcf2d38b/cgame/gs/task/TaskProcess.cpp#L2424-L2444)
- **Рецепты и персонажи.** Для заданий подтверждены связи с предметом, который можно изготовить, и требования к ремесленному навыку. Прямая ссылка на ID рецепта в изученных полях заданий и операциях ИИ пока не обнаружена. Рецепты и их материалы читает сервис изготовления NPC из `elements.data`. Для персонажа задания и ИИ могут проверять класс. `clsconfig` задаёт начальный шаблон при создании, а данные существующего персонажа хранятся в WDB. [Требования к навыку](https://github.com/huzeming/176source/blob/c0992a29c0848de4de139a8958ceb11edcf2d38b/cgame/gs/task/TaskTempl.inl#L975-L991) · [Загрузка рецептов](https://github.com/huzeming/176source/blob/c0992a29c0848de4de139a8958ceb11edcf2d38b/cgame/gs/npcgenerator.cpp#L1627-L1702) · [Ролевые таблицы WDB](storage-and-recovery.ru.md)

Замену `aipolicy` и `tasks` нужно сверять с выбранными `elements`, спавнами и клиентом. Совпадение ID сохраняет адресацию, а одинаковые игровые поля нужны для сохранения поведения. Проверка ссылок в файлах покрывает только изученные типы записей. Проверка смешанного комплекта в игре отдельно нужна для выдачи, выполнения и сдачи заданий, вызова спавнов и загрузки сохранённого прогресса. [Данные клиента](client-server-sync.ru.md)

### Проверка связей перед упаковкой

Будущая утилита проверяет итоговое дерево после выбора файлов. Первая версия берёт из конфигурации GS пути к активным таблицам и картам и строит индексы ID с учётом таблицы и типа записи. Для заданий учитываются дочерние и динамические записи.

1. Проверить `npcgen → elements` для спавнов NPC и монстров, `elements → aipolicy` для политик монстров и `elements → tasks` для сервисов выдачи заданий.
2. Вывести путь и ID исходной записи, поле ссылки и ожидаемые таблицу и ID. Контрольный пример — подмена RU `tasks.data` на CN при сохранении Linear `elements.data`. Отчёт должен показать ссылку из сервиса 43097 на отсутствующий квест 36625.
3. Начать с отчёта и сверки с базовым комплектом. Штатные поставки уже содержат неразрешённые ссылки в шаблонах. После первого прохода добавить проверку контроллеров в контексте конкретной карты и проверку дерева с учётом приоритета `overlay`.

ID помогают найти отсутствующую цель и сопоставить записи разных редакций. Для проверки поведения нужна отдельная сверка полей. Например, в обеих редакциях есть политика 3641 с разными умениями. Выбор совместимого комплекта остаётся явным решением при сборке.

## Что меняют сохранённые редакторы

- **Карты и спавны.** MyAceEditor показывает и редактирует рельеф, объекты, регионы, переходы и пути патрулей. В `npcgen` есть координаты, ID шаблонов, количество, разброс, респаун, ресурсы, динамические объекты и контроллеры. Эти же группы видно в сохранённых sNPCedit и Npcgen Editor by Luka. `precinct.clt` может содержать названия зон и меток, поэтому в карте бывают и текстовые поля. [Возможности редактора карт и NPC](https://github.com/ipasetto/MyAceEditor/blob/b1fe6f8437625d7d5844b58214bdd303c475cc0c/README.md#L128-L195) · [Формат спавнов](https://github.com/ipasetto/MyAceEditor/blob/b1fe6f8437625d7d5844b58214bdd303c475cc0c/PerfectWorld/NpcGenFile.cs#L78-L156)
- **Шаблоны `elements`.** Схема MyAceEditor описывает имена, параметры монстров, модели, добычу, ингредиенты и результат рецептов. Мастер NPC создаёт сервис изготовления и связывает его с рецептами. Перенос строк возможен по имени таблицы, ID и имени поля. Общий редактор таблиц хранит `TALK_PROC` как отдельный непрозрачный блок. [Схема таблиц v386](https://github.com/ipasetto/MyAceEditor/blob/b1fe6f8437625d7d5844b58214bdd303c475cc0c/PerfectWorld/cfg/PW_1.7.6_v386.cfg#L194-L347) · [Сборка сервиса NPC](https://github.com/ipasetto/MyAceEditor/blob/b1fe6f8437625d7d5844b58214bdd303c475cc0c/PerfectWorld/NpcBuilder.cs#L197-L248) · [Перенос строк](https://github.com/ipasetto/MyAceEditor/blob/b1fe6f8437625d7d5844b58214bdd303c475cc0c/PerfectWorld/ElementsTranslator.cs#L18-L38)
- **ИИ и квесты.** AipolicyEditor 1.7.6 v40 поддерживает изменение условий и операций триггера, включая цели и текст. В сохранённом sTASKedit v2.191 есть редактирование диалогов, целей, NPC и наград. Схема v191 и логика сохранения также есть в MyAceEditor. [Редактор ИИ](https://github.com/shakl-team/AipolicyEditor.1.7.6) · [Схема заданий](https://github.com/ipasetto/MyAceEditor/blob/b1fe6f8437625d7d5844b58214bdd303c475cc0c/PerfectWorld/TaskLayout.cs#L194-L208) · [Мастер задания](https://github.com/ipasetto/MyAceEditor/blob/b1fe6f8437625d7d5844b58214bdd303c475cc0c/PerfectWorld/QuestBuilder.cs#L474-L513)
- **Созданные персонажи.** Сохранённая PWAdmin правит ролевые данные через `exportrole` и `updater`. Это отдельная операция со значениями в WDB, тогда как `clsconfig` применяется к шаблону нового персонажа. Возможности сверены по сохранённому коду, схеме форматов и ресурсам инструментов. Проверка редакторов была статической. MyAceEditor указывает 1.5.5 как проверенную автором версию. Схемы v386 и v191 здесь проверялись чтением файлов 1.7.6.

## Варианты пакетов

В обоих вариантах серверный пакет содержит программы и серверную обвязку. В замер вошли 10 основных ELF Linear и 6 Lua-файлов, всего **560,4 МБ**. Две дополнительные библиотеки `libskill.so` и `libtask.so` добавят **152,5 МБ**, если войдут в комплект. Ниже используется базовая версия карт для выбранного билда. Переопределения спавнов и таблиц пользователь кладёт по тем же относительным путям в подключённый `/opt/pwserver/overlay`. [Схема размещения и ссылок](package-architecture-proposal.ru.md#размещение-файлов-пакетов)

| Разбиение после серверного пакета | Базовый пакет | Комплект RU | Комплект CN |
| --- | --- | ---: | ---: |
| `perfect-world-data` и языки | Карты, одна выбранная редакция `elements`, спавнов, `clsconfig` и остальных базовых таблиц. Около **4,51–4,52 ГБ**. | **187,4 МБ**, два файла | **176,5 МБ**, два файла |
| `perfect-world-maps` и локализованные комплекты данных | **4,41 ГБ** общих ресурсов из каталогов карт. | **292,9 МБ**, 251 файл | **277,9 МБ**, 251 файл |

В первом варианте языковой пакет заменяет `aipolicy` и `tasks`. Имена, описания и диалоги из `elements` сохраняют язык базового пакета. Разные комплекты `aipolicy` и `tasks` должны подходить к выбранной редакции данных. Во втором варианте каждый локализованный комплект несёт собственные `elements`, `npcgen` и `clsconfig` вместе с `aipolicy` и `tasks`. Это сохраняет сочетания из поставки и позволяет менять их независимо от больших файлов карт. Ссылки по ID и соответствие версии клиента проверяются для каждого комплекта.

### Разбиение для первого DEB

Фиксируем три роли пакетов, чтобы следующие локализации добавляли варианты контента к той же сборке. В первом DEB используем один проверяемый серверный комплект и один выбранный комплект локали.

| Пакет | Содержимое |
| --- | --- |
| `perfect-world-server` | Исполняемые файлы, нужные библиотеки, конфиги служб и `gamedbd/serverlist.sev`, SQL и Bash/systemd-обвязка. |
| `perfect-world-data` | Общие карты, коллизии, навигация и совместимые серверные `region.sev`, `precinct.sev`, `path.sev` и другие ресурсы, нужные всем профилям. |
| `perfect-world-locale-<язык>` | Один согласованный набор выбранных игровых `.data`, включая `elements`, задания, ИИ, магазин и спавны. `npcgen` берём с сервера и можем переиспользовать в нескольких профилях. |

Общий пакет и пакет локали используют `/opt/pwserver/data` с одним владельцем каждого файлового пути. Устанавливается одна локаль для выбранной версии данных. Клиентские PCK/CLT входят в соответствующий клиентский комплект. Поддержка `zh-CN`, `ru`, `en` и `pt-BR` требует отдельных проверок совместимости. Если ресурсу нужна отдельная редакция, меняется правило для его пути и выбранный источник. Проверка ссылок и запуск с каждым клиентом относятся к подготовке релиза и могут запускаться отдельно от обычной сборки DEB. [Клиенты, карты и ридеры](server-resource-editors.ru.md#клиенты-176-en-и-br) · [Дерево установки](package-architecture-proposal.ru.md#размещение-файлов-пакетов)

### Где лежат файлы спавна

Разбиение проходит по файлам внутри каталога карты. Оба пакета устанавливают свои файлы в одно дерево `/opt/pwserver/data`. Каталоги могут быть общими для DEB-пакетов, а у каждого файла один пакет-владелец. [Общие каталоги в dpkg](https://github.com/guillemj/dpkg/blob/main/src/main/archives.c)

```text
/opt/pwserver/data/gamed/config/a108/
├── map.bht       # perfect-world-maps
└── npcgen.data   # выбранный комплект, например perfect-world-russian
```

В `binary/gamed/config/a108/` создаются ссылки на отдельные файлы. Например, `npcgen.data` указывает на `/opt/pwserver/data/gamed/config/a108/npcgen.data`. Одноимённый файл под `overlay/` по тому же относительному пути получает приоритет. `gs` открывает штатный путь карты с именем из `NPCGenFile`. Для составных карт комплект спавнов включает файлы `npcgen/npcgen_N.data` по путям фрагментов. [Дерево запуска](package-architecture-proposal.ru.md#размещение-файлов-пакетов) · [Загрузка карты](https://github.com/huzeming/176source/blob/c0992a29c0848de4de139a8958ceb11edcf2d38b/cgame/gs/mapresman.cpp#L111-L118) · [Загрузка фрагментов](https://github.com/huzeming/176source/blob/c0992a29c0848de4de139a8958ceb11edcf2d38b/cgame/gs/mapresman.cpp#L218-L237)

### Состав замера

Если после отбора использовать суффикс `.data` как критерий языкового пакета, из измеренного набора в него попадут 244 файла. Их объём до сжатия составляет **270,0 МБ RU** и **255,0 МБ CN**. ## DEB и слои Docker

Размеры содержимого в десятичных МБ до и после сжатия. Для каждой группы собран контрольный TAR. XZ Utils 5.8.3, уровень 6, два потока для малых групп и четыре для карт. Gzip измерен через zlib с уровнем 6, Zstandard через libzstd 1.5.7 с уровнем 3. Это оценка размера содержимого `.deb` и слоёв образа. Итог зависит от списка файлов, метаданных, порядка и разбиения на слои.

Для варианта с `perfect-world-data` сумма замеров карт и остальных данных даёт около **1,36 ГБ XZ**, **2,00 ГБ gzip** или **1,84 ГБ Zstandard**. Это оценка по двум отдельно сжатым группам. При упаковке одним потоком размер будет зависеть от итогового TAR.

Отдельно `7z a -t7z -mx=9 -mmt=2` сжал RU `tasks.data` и `aipolicy.data` в **11 005 904 байта**. 7-Zip 26.06 записал один solid-блок LZMA2 со словарём 192 МиБ. `tar.xz` той же пары с уровнем 6 занял **10 994 860 байт**. Оба результата около 11 МБ.

- **DEB.** В Debian 13 `dh_builddeb` вызывает `dpkg-deb`. По умолчанию полезная нагрузка хранится в `data.tar.xz`, XZ с LZMA2 уровня 6. Поддерживаются gzip и zstd, тип и уровень задаются через `-Z` и `-z`, в том числе через `dh_builddeb --`. [Формат DEB](https://manpages.debian.org/trixie/dpkg-dev/deb.5.en.html) · [dpkg-deb](https://manpages.debian.org/trixie/dpkg/dpkg-deb.1.en.html) · [dh_builddeb](https://manpages.debian.org/trixie/debhelper/dh_builddeb.1.en.html)
- **Docker.** При установке DEB в контейнер слой содержит распакованные файлы. BuildKit по умолчанию сжимает новые слои gzip, также поддерживает zstd для OCI-слоёв. Точный размер передачи берётся из `layers[].size` манифеста нужной платформы. Если карты собраны отдельным слоем с тем же digest, разные языковые образы могут использовать один слой. Файлы из bind mount или volume при запуске поступают из внешнего хранилища. [Экспорт BuildKit](https://docs.docker.com/build/exporters/image-registry/) · [Сжатие и OCI](https://docs.docker.com/build/exporters/#compression) · [Слои образов](https://docs.docker.com/learn/content/how-image-layers-and-the-build-cache-work/) · [Манифест OCI](https://github.com/opencontainers/image-spec/blob/main/manifest.md)
