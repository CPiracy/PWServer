# Оставшиеся файлы PWServer 4311 после фильтрации

Исходный снимок от 26 ноября 2026 года. В `builder/config.json` от одного источника `Linear/PWServer176.7z` осталось **3 984 файла с разными назначениями**. Правила билдера взяты из коммита `a778948`. SHA-256 снимка конфига — `83e8b2d52ea28ca6de9e3c84b663e7168a55acbcaad5bbf479a5a5fc6f15cd46`.

В каталогах карт 3 888 файлов, на верхнем уровне `gamed/config/` — 26, в остальных каталогах серверного дерева — 67. Ещё три входа находятся вне `root/pwserver/`. Это `home/license.conf` и два SQL-дампа. Все 3 981 назначения внутри серверного дерева сопоставились со строками прежней описи. Из них 15 ещё проходят отбор, хотя в прежней описи им было назначено исключение. [Прежний разбор](pwserver-files-review.ru.md) · [Пофайловая опись](evidence/pwserver-files/assessment.csv)

Из архива прочитаны 384 выбранные записи, включая все 342 `.conf`, семь `.lua`, два `.xml`, текстовые и служебные файлы. Явные ссылки сверены с конфигурацией. Поведение при запуске относится к сохранённым проверкам именно Build 4311. H176 и S172 помогают объяснить загрузчики и форматы. Их связь с конкретным бинарником проверяется отдельно. [Ревизии исходников](source-coverage.ru.md) · [Запуск сокращённого дерева](../experiments/image-file-validation/image-file-validation.ru.md) · [Запуск с чистой WDB](../experiments/package-layout/clean-start-experiment.ru.md)

В исходном снимке уже учтены допустимые расширения, ASCII в исходном пути и исключение содержимого `dbhome/`. В конфиге отсутствуют архивные `.log`, `.bak` и `.dataBAC`, восемь нечисловых `.wmap` из `world/watermap/` с символами вне ASCII и файлы под `gamed/config/мусор/`. Группировка уже выбрала по одному варианту для `tasks.data`, `aipolicy.data`, `elements.data`, `rare_item.conf`, `clsconfig` и запасных версий программ. Для этих вариантов отдельное правило удаления не требуется. [Правила слоёв и выбор версий](package-builder-filter-rules.ru.md)

## Согласованные правила отбора

В коммите `760cb27` каждый слой проверяет полный исходный путь через `fullmatch`. Для прохождения слоя достаточно совпадения с `rule` или с одним из его `exceptions`. Путь должен пройти все слои. После этого билдер вычисляет назначение, группирует варианты и выбирает файлы. [Правила в коде](../builder/src/libs/config/config_builder.py)

| Слой | Какие пути проходят |
| --- | --- |
| Расширения | Одно из 17 расширений в `_PW_EXTENSIONS` или имя файла без точки. |
| Имена | Все символы исходного пути, включая имена каталогов, входят в ASCII. |
| Рабочие данные и резервные копии | В пути нет каталогов `dbhome` и `backup`. Правило действует на любой глубине. Для источника-каталога учитывается и путь к самому источнику. |
| Отчёты и журналы | Путь не заканчивается на `report` или `log.txt`. Суффикс `report` намеренно охватывает будущие отчёты. Журналы исключаются и в `gdeliveryd/`. |
| TXT | Файлы `.txt` проходят только в дереве `gdeliveryd/`. |
| XML | Из `.xml` проходит только путь с окончанием `gacd/gacd.xml`. |
| Имена без точки в каталогах карт | Такое имя исключается под вложенным каталогом `gamed/config/`. Файл `gamed/config/filters` лежит на верхнем уровне и проходит. |
| `.data` и `.sev` в каталогах карт | Во вложенных каталогах `gamed/config/` проходят `.data` с именем файла, начинающимся на `npcgen`, и четыре точных имени `.sev` — `precinct.sev`, `region.sev`, `path.sev`, `map_desp.sev`. Данные на верхнем уровне `gamed/config/` этот слой пропускает. |

Утилиты и сценарии обслуживания GameDB, `gamed/foo`, `gamedbd/cupon` и общие игровые ресурсы остаются в конфиге. Файлы рельефа, навигации и клиентских областей проходят при соблюдении общих условий по пути и расширению.
