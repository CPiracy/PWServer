# Проверка раскладки файлов и пути лицензии

18 ноября 2026 года. Build 4311 из Linear запущен в изолированной WSL от UID 1000 с точными путями `/opt/pwserver/{binary,data,overlay}`. Исходное дерево `/root/pwserver` было недоступно процессам. Стенд использовал отдельную MariaDB по TCP, копии двух архивных WDB и приватную сеть с loopback. Автоматический запуск из DEB и вход клиентом остаются отдельными проверками. [Предлагаемая раскладка](../../research/package-architecture-proposal.ru.md#размещение-файлов-пакетов)

Для проверки взяли 3 974 файла [ранее испытанного набора](../image-file-validation/image-file-validation.ru.md). В `binary` разместили 10 исполняемых файлов и 6 Lua-файлов, в `data` — 3 942 ресурса, в `overlay` — 16 конфигов и отдельно предоставленный файл лицензии. В дереве запуска создали 3 958 относительных ссылок на конфиги и ресурсы. SHA-256 всех десяти исполняемых файлов совпали с предыдущим прогоном. Каждая служба работала из своего подкаталога в `binary`.

## Доступ к лицензии

- Литерал `/home/license.conf` найден в ELF `gauthd`, `gamedbd`, `gfactiond`, `gdeliveryd` и `glinkd`. При наличии файла в `overlay` и пустом приватном `/home` процесс `gauthd` завершился по `SIGUSR1` до появления слушателя. Клиент лицензии в доступном исходнике обращается к этому абсолютному пути перед загрузкой рабочего конфига.
- Подключение файла из `overlay` только для чтения по пути `/home/license.conf` дало успешное открытие файла штатным `gauthd`. Трассировка показала открытие по старому имени, а проверка метаданных подтвердила тот же файл. Отдельная проба временного юнита systemd с `ProtectHome=tmpfs` и `BindReadOnlyPaths=` подтвердила чтение файла под старым именем внутри юнита. Снаружи этого пути не появилось.
- При совпадении времени изменения `license.conf` и `gauthd/gamesys.conf` до секунды `gauthd` проверил доступность `gamesys.conf`, но не открыл его и завершился с ошибкой SQL-подключения. Доступная реализация `Conf` хранит одну метку `st_mtime` и сравнивает её при переключении файла. В повторе с изменением только `mtime` копии `license.conf` на 60 секунд авторизация открыла слушатель и установила SQL-сессию с `pw176`. Следует проверять метки целей ссылок при подготовке конфигов. [Загрузчик конфигов](https://github.com/huzeming/176source/blob/c0992a29/share/common/conf.h#L24-L46)

## Запись при запуске

При первоначальном монтировании всех трёх деревьев только для чтения девять демонов запустились, но `gs01` завершился с кодом 255 и сообщением о недоступной записи. С доступным на запись `binary` поднялись обе карты. В `binary` появились четыре обычных файла: `gamed/foo` и `lualog.txt` в каталогах `gauthd`, `gamedbd`, `gdeliveryd`.

В финальном варианте все три дерева снова смонтированы только для чтения. Для этих четырёх путей созданы симлинки на заранее существующие файлы в отдельном каталоге состояния. `dbhome`, директории резервных копий WDB и общие журналы также доступны по ссылкам на записываемое состояние. Финальный прогон подтвердил девять слушателей, работу SQL-сессий со схемами `pw176` и `licenseservice`, регистрации обеих карт в `gdeliveryd` и появление их UNIX-сокетов. Карты были активны одновременно.

| Карта | Индекс / worldtag | От старта процесса до регистрации и готовности |
| --- | --- | ---: |
| `gs01` | `1 / 1` | 4,19 с |
| `is61` | `101 / 161` | 7,16 с |

После регистрации второй карты наблюдение продолжали 8 секунд. При остановке девять демонов и MariaDB вернули код 0, карты завершились по `SIGTERM`. Прогон проверяет запуск и маршрутизацию, а также доступность состояния по ссылкам на существующих WDB. Инициализация пустых WDB, сохранение персонажа, обновление пакетов и полный комплект юнитов не входили в этот прогон.
