# Выгрузка пустой карты в Build 4311

17 ноября 2026 года на рабочей ВМ проверили остановку отдельного GS при активном клиенте на другой карте. Целевая `is61` имела `index=101`, `worldtag=161`. Единственный игрок `tptest` находился в Тайной деревне на `gs02__` (`index=2`, `worldtag=1`) в тестовой конфигурации из [опыта с Сетью](../teleport-network/plan.ru.md).

## Результат

| Время ВМ, UTC+3 | Наблюдение |
| --- | --- |
| `17:26:47` | `world2.log` зарегистрировал одного игрока на GS `2`. |
| `17:27:27` | GS `101` сообщил 0 игроков. Предыдущие замеры тоже давали 0. |
| `17:29:38` | После сверки активной роли на GS `2` послали `SIGTERM` процессу `is61` с PID `8700`. |
| `17:29:39` | PID карты завершился, её TCP-порт `11971` освободился. Игровое соединение с `glinkd` сохранило тот же inode `368014`. |
| `17:30:36` | На шлюзе всё ещё было то же соединение. |
| `17:32:24` | `gdeliveryd` снова зарегистрировал GS `101`, `worldtag=161`. Карта запустилась с PID `23026` и подключилась к шлюзу и БД. |
| `17:32:39` | `gs01` и `gs02__` вновь добавили dispatcher `101`. Сессия `tptest` оставалась на прежнем соединении. |

После остановки пользователь подтвердил, что игра в Тайной деревне продолжала работать как обычно.

## Где смотреть занятость

В рабочей MariaDB `pw176.online` содержит одну колонку `ID` с идентификатором аккаунта. Во время опыта в таблице была одна запись тестового аккаунта, в том числе при остановленной `is61`. В WDB `GRoleStatus` хранит `worldtag` и последнюю сохранённую позицию персонажа. Эти поля читаются и у выгруженной из мира роли.

Для счётчика по карте использовать данные работающего GS. В Build 4311 `world2.log` получает строки `gameserver <index> , 用户数目:<count>` примерно раз в четыре минуты. Сопоставлять `index` с алиасом и `worldtag` по конфигурации и регистрации в `world2.trace`. Периодический журнал пригоден для поиска простаивающих карт. Перед автоматической остановкой карты нужна свежая проверка текущих игроков, переходов и сохранений.

## Как повторить

1. Оставить один игровой клиент на другой карте. Сверить `index` текущего GS по последнему успешному входу или `SwitchServerSuccess`. Выбрать целевую карту, на которой журнал стабильно показывает 0 игроков.
2. Зафиксировать PID и рабочий каталог цели, а также идентификатор активного TCP-соединения. На стенде использовали следующие команды.

   ```bash
   ps -C gs -o pid,args
   grep -aE 'gameserver (101|2) ?,' /root/pwserver/logs/world2.log | tail -8
   grep -E 'PlayerLogin userid|RoleStatusManager: RoleOffline|SwitchServerStart|switch user' /root/pwserver/logs/world2.trace | tail -12
   ss -Hntpe state established '( sport = :29000 )'
   ```

3. Ещё раз сверить единственную активную роль и её GS. Послать `SIGTERM` подтверждённому PID пустой `is61`. Проверить завершение процесса, закрытие `11971` и сохранение того же соединения на `29000`. Дождаться, пока игрок сделает несколько шагов на другой карте.
4. Запустить `./gs is61 gs.conf gmserver.conf gsalias.conf` из прежнего рабочего каталога и с прежним окружением. Проверить новый PID, свежую регистрацию с индексом `101` и тегом `161`, подключения к шлюзу и БД и `Add dispatcher 101` у соседних GS.

Опыт с `SIGTERM` подтвердил изоляцию активного клиента при остановке пустого процесса. Для автоматической выгрузки ещё предстоит подтвердить адресное завершение с записью, проверку входа во время остановки и учёт переходов, которые уже начались.
